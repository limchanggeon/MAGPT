## 수정한 문제

1. **캐릭터 DB 조회**: 캐릭터마다 연결을 새로 열고 스냅샷을 찾던 경로를 두 연결로 줄였다. 캐릭터를 먼저 읽고
   인덱스로 최신 두 스냅샷의 rowid만 찾는다. 이름/대표 여부만 필요한 호출은 스냅샷을 읽지 않는다.
2. **넥슨 캐시**: 같은 대상을 동시에 물으면 진행 중인 요청 하나를 공유한다. 반환값은 독립 복사해 프리셋 조작이 캐시를 바꾸지 않게 했다.
   모든 캐시 종류를 합쳐 64개로 제한하며 기존 180초 TTL을 유지한다. 실패는 캐시하지 않는다.
3. **키 교체·삭제**: 서버/화면 캐시와 계정 목록·경험치·받은 기록 날짜를 무효화한다. 키 변경 중 완료된 이전 요청은 새 캐시나
   계정 목록에 저장하지 않는다. 검증에 쓴 캐릭터 목록은 재사용해 바로 뒤에 같은 API를 또 부르지 않는다. 저장된 수익·캐릭터·강화 이력은 유지한다.
4. **수익 집계**: 전체 자료를 기간마다 다시 순회하던 경로를 한 번의 주/월 분류로 바꿨다. 합계·표시 순서·목요일 주간 경계는 유지한다.
5. **강화 계산**: 비용·횟수·파괴가 사용하는 동일 전이행렬을 한 번만 소거한다. 비용표는 최대 300개 캐시하고 반환 리스트는 분리한다.
   기록 분석에서 동일 시도 비용을 두 번 계산하던 것도 제거했다.
6. **입력 검증**: NaN·무한대·소수 성/장비 레벨을 사용자 오류로 처리한다. 중복 할인은 한 번만 적용하고 여러 MVP 등급은 거절한다.
   대화의 최대 성 선택지는 계산기의 같은 함수를 쓴다(95~107레벨 10성, 108~127레벨 15성).
7. **수집 동시성**: 표 초기화는 Store당 한 번 실행하며 실패하면 재시도한다. 동일 캐릭터 스탯 수집 및 공지 수집을 직렬화한다.
   스탯 캐시만 읽는 화면 요청은 외부 수집 완료를 기다리지 않는다. 비교 유저의 호출 몫·간격과 목표/후보 큐 교체도 보호한다.
8. **화면 요청·실패 처리**: 클릭 뒤 hashchange가 다시 로딩하던 경로, 동일 GET의 동시 호출, 숨긴 캐릭터 탭의 폴링을 줄였다.
   목록만 실패했는데 이미 받은 대화 답이 지워지던 문제를 수정했다. 키/수익 기간 변경 뒤 도착한 이전 응답도 무시한다.
9. **비교 표**: `createElement('tr behind')`로 뒤처진 부위가 있는 표를 만들다 멈추던 오류를 정상 `tr`과 class로 수정했다.
   브라우저에서 재현했고, 실제 `renderPeers`를 실행하는 Node 회귀 검사를 추가했다.
10. **자산·업데이트·도구**: 요청하던 PNG 두 파일을 허용 목록으로 제공하고 정확한 MIME을 쓴다. 설정의 오래된 미구현 안내와 초기 버전 표시도 정리했다. 업데이트 SHA256은 스트리밍으로 확인한다.
    개발용 스탯 점검은 앱과 같은 수집 함수를 쓰며, 식별자가 없으면 추가 API 호출 없이 실패한다.
