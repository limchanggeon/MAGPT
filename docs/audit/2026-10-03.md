## 수정 사항

1. **넥슨 호출 간격**(`adapters.py`): 기존 방식은 대기 시간을 미리 예약해 429 휴식 전에 예약한 스레드가 그대로 호출했다.
   늦게 깨어나면 다음 호출과 겹치기도 했다. 깨어난 뒤 실제 허용 시점을 다시 확인하며 간격 0.25초와 최대 4회 시도 정책은 유지했다.
2. **프리셋 선택**(`statcalc.py`): 같은 장비 이름·스타포스·잠재 줄이라도 추옵·주문서·소울 등이 다른데 비교에서 생략했다.
   원본 장비 전체를 대조한다. 소울과 합산 옵션만 바뀐 프리셋이 실제로 선택되는 회귀 검사로 확인했다.
3. **스탯 합산**(`statcalc.py`): `Ledger.add` 때 스탯/종류/출처별 합계를 함께 유지한다. 교체마다 수천 출처 줄을 다시 순회하지 않는다.
   원래 출처 설명 줄과 분류 변경 동작은 유지한다. 내부 원장 변경은 `add`를 사용한다.
4. **목표 계산**(`goals.py`): 시작 날짜·존재 여부는 SQL로 읽고 평균에 필요한 최근 30일만 가져온다.
   내일 기록이 목표의 실제 수익으로 들어가지 않게 했으며, 아주 느린 획득 속도에서도 날짜 계산 오류로 500을 내지 않는다.
5. **경험치 수집**(`goals.py`): 같은 캐릭터의 날짜 수집을 직렬화하고 여러 캐릭터의 캐시 쓰기는 최신 값을 읽어 병합한다.
   인증/429 뒤 날짜를 계속 조회하지 않고, 이미 받은 날짜는 보존한 뒤 오류를 알린다.
6. **강화 기록**(`history.py`): 외부 401/403/429가 앱에서는 502로 변환되어 날짜 루프가 계속되던 문제를 수정했다.
   외부 상태를 확인해 중단하고, 뒤따르는 장비 레벨 조회도 하지 않는다.
7. **후보 수집**(`peers.py`): 오류 전에 후보를 큐에서 삭제하지 않는다. 재시도 성공 뒤에만 큐/집계를 갱신하며,
   존재하지 않는 캐릭터(404)는 넘어간다. 프리셋용 임시 스탯은 최대 32명이고 탈락/완료 후보는 즉시 제거한다.
8. **이미지 캐시**(`server.py`): 최대 96개뿐이던 제한(각 3MB이면 약 288MB)에 **본문 합계 12MiB** 제한을 더했다.
   잠금과 진행 중 요청 공유로 동시 다운로드·LRU 충돌을 줄인다. 실패는 재시도할 수 있다. 정적 이미지와 API 키 캐시는 별개다.
9. **캡처 입력**(`static/app.js`): 파일 읽기 시작부터 요청을 구분해 오래된 파일과 모델 응답을 무시한다.
   초기화 후 응답·차이를 되살리지 않고, 0개 조각/0메소도 이전 폼 값을 덮는다. 재획비가 비어 있으면 이전 캡처의 개수도 지운다.
10. **백업**(`backup.py`): 같은 초/같은 이름의 백업을 독립 파일로 만들고 본문 백업과 정리·목록 조회를 잠금으로 보호한다.
    파일 수정 시각으로 최신 5개를 유지하며 실패한 미완성 파일은 제거한다. 임시 파일 생성 권한은 POSIX 기준 0600이다.

`earnings.py`의 금액 상한 주석도 실제 상수(1조)에 맞췄다. 상한값은 변경하지 않았다.
