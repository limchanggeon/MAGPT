# 추가 전수 점검·저장소와 대화 최적화 · 2026-10-03

사용자의 반복 점검 요청에 따라 이전 점검 결과를 보존하고 저장소·시세·화면의 남은 병목과 경합을 추가 조사했다.
기준은 HEAD `b596145`에 이전 로컬 수정이 적용된 **Python 464개 통과 작업 트리**다. 깨끗한 HEAD와의 비교가 아니다.
버전은 0.4.6이며 이번 변경도 로컬 미커밋·미릴리스다.

## 조사와 변경

전체 Python 회귀 검사, 앱·도구의 구문/미사용 코드/미정의 이름 검사, JS 세 파일 구문 검사와 두 브라우저의 6탭 동작을 다시 확인했다.
이번 상세 소스 검토는 `core.py`, `prices.py`, `chat.py`, `auction.py`, `static/app.js`, `static/characters.js`의 저장·검색·후속 요청 경로에 집중했다.
나머지 영역의 이전 상세 검토는 [앞선 보고서](2026-10-03.md)에 기록되어 있다. 최신 게임 규칙·외부 API 정책을 다시 확인한 조사는 아니다.

1. **근거 검색**: 미승인·만료·미래 적용·다른 서버 자료의 본문까지 가져오던 경로를 메타데이터 선별 후 본문 조회로 바꿨다.
   두 조회는 같은 읽기 트랜잭션에서 수행하며 500개씩 조회해 오래된 SQLite의 매개변수 제한을 지킨다.
   근거 문단 분리는 최종 5개에만 수행한다. 점수·동점 최신순·전체 일치 문서의 버전 충돌 판단은 유지한다.
2. **노작값 조회**: 장비/급/시각 인덱스를 추가했다. 같은 초의 기록도 `rowid DESC`를 함께 사용해 가장 늦게 저장한 값을 선택한다.
   급이 일치하는 값 우선, 없으면 같은 장비의 최신 값으로 대체하는 기존 규칙은 유지한다.
3. **일일 집계**: 최근 1,000건에서 세던 조회 출처 기록을 해당 날짜 전체의 SQL 집계로 바꿨다.
   사용자 입력 1,000건 뒤에 가려진 외부 조회 기록도 한도 계산에 포함한다.
4. **시세 경합**: 같은 Store에서 한도 확인→외부 조회→저장을 직렬화하고 저장값을 다시 확인한다.
   같은 장비의 동시 요청 6개는 외부 조회 1회가 되며 서로 다른 장비도 남은 한도 1건을 공유한다.
   이미 저장된 값은 이 잠금을 기다리지 않는다. 실패한 조회는 잠금을 풀어 재시도할 수 있다.
5. **쓰기 뒤 GET**: 성공한 POST 뒤에는 이전 GET을 공유하지 않는다. 이전 GET의 완료가 더 새 GET의 공유 항목을 삭제하지 않도록 한다.
6. **대화 전환**: 마지막으로 선택한 대화만 메시지/주제를 반영한다. 새 대화는 이전 읽기를 무효화한다.
   읽는 동안 질문 제출을 막고 현재 읽기가 성공/실패했을 때 복구한다. 오래된 실패도 현재 로딩 상태를 바꾸지 않는다.
   목록 조회에도 순서 검사를 넣고 목록 갱신 실패는 별도 오류로 처리한다.
7. **키 변경**: 수익 화면의 계정 목록 조회 시도 상태를 초기화하고 이전 키의 조회 완료로 수익 화면을 다시 갱신하지 않는다.

변경 파일: `mepiti/core.py`, `prices.py`, `static/app.js`, `static/characters.js`,
`scripts/audit_benchmark.py`, `tests/test_frontend.js`, 신규 `tests/test_audit_storage.py`와 이 보고서/원자료,
`README.md`, `IMPLEMENTATION.md`, `HANDOFF.md`.
사용자의 비추적 `Maple_Equipment_Recommendation_Pipeline.md`는 수정하지 않았다.

## 검증

- Python **474개 통과**(직전 464 + 신규 독립 검사 10개), 15.811초. 신규 검사는 대규모 근거/충돌/승인 취소,
  같은 초의 시세, 1,000건 이상 집계, 중복·한도 경합, 저장값 즉시 반환, 실패 후 재시도를 확인한다.
- 수정 전 작업 트리에 신규 검사를 적용했을 때 3개 실패·2개 오류. 그중 1개 오류는 새 집계 메서드가 없는 영향이며,
  나머지는 이전 값 선택·중복 조회·한도 초과·잘린 집계의 재현이다.
- Node 실제 함수 검사: GET 공유·재시도·쓰기 분리, 쓰기 뒤 오래된 GET 배제, 대화 응답 역전·새 대화·실패·목록 역전·키 초기화,
  기존 비교 표/캡처 검사 통과. 수정 전 JS에서는 쓰기 후 GET 검사 실패(필요한 3개 요청 대신 2개).
- 고정 시드 1003의 검색 128조건은 이전/이후 반환 필드 전체가 일치했다. 기존 5개 바깥의 버전 충돌도 검사한다.
- Chromium/WebKit에서 지연된 A 응답보다 B를 먼저 반환한 뒤에도 B만 표시하며, 새 대화 후 A 응답은 폐기한다.
  두 브라우저 모두 6탭·비교 표·재획 저장·캡처·0조각 적용·목록 실패 뒤 답변 유지 통과, JS 오류 0개.
- Python compileall·Ruff, JS 구문 3개·Node, `git diff --check` 통과.

## 성능

같은 기기에서 수정 전/후를 순서대로 실행하고 각 경로 5회 중앙값을 비교했다.
임시 자료는 문서 1,000개(검토 승인 50개, 본문마다 2,000줄), 노작값 10,000건이며,
기존 캐릭터 79명·스냅샷 2,370개·수익 10,000건·스탯 출처 3,000줄도 유지했다.

| 경로 | 수정 전 | 수정 후 | 시간 감소 |
|---|---:|---:|---:|
| 근거 검색 | 48.383ms | 18.863ms | 61.0% |
| 노작값 100회 조회 | 96.941ms | 8.079ms | 91.7% |
| 일일 조회 출처 집계 | 5.169ms | 0.427ms | 91.7% |

**9개 측정 경로 모두 반환 JSON SHA-256 일치**. 위 세 경로 이외의 시간 차이는 이번 최적화 효과로 주장하지 않는다.
실제 API 지연·운영 DB 규모·설치 앱 속도에 대한 수치는 아니다.
[측정 원자료](2026-10-03-round3-benchmark.json)에 전/후 코드 해시·전체 측정·화면 결과를 기록했다.

## 남은 사항과 다음 작업

- 외부 조회 한도 집계는 기존처럼 **저장된 성공 결과**를 센다. 실패/빈 결과 등 모든 실제 경매장 호출 횟수나 플랫폼 잔여 한도를 대신하지 않는다.
- 시세 잠금은 같은 Store/앱 프로세스 범위다. 여러 앱 인스턴스의 외부 조회를 묶지는 않는다.
- 검색은 여전히 메타데이터와 유효 문서를 순회한다. 전체 대화/수익 조회도 자료량에 따라 증가한다. 페이지 조회/검색 인덱스는 운영량 근거가 더 필요하다.
- 실제 사용자 DB·OS 키체인·실제 넥슨/경매장·유료 모델·Windows·패키지 빌드·원격 CI·릴리스는 이번에 실행하지 않았다.
- 로컬 변경을 배포하려면 macOS/Windows 빌드·설치/업데이트와 실제 연결을 확인한다. 기존 미완료 스탯·추천 기능은 HANDOFF의 목록을 유지한다.
